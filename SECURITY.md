# Безпека SmartLib

## Повідомлення про вразливість

Якщо ви знайшли вразливість у SmartLib, **не створюйте публічний issue з подробицями**. Напишіть команді напряму (особисте повідомлення або командний чат) і вкажіть:

- що саме не так і в якому файлі чи вікні;
- як відтворити проблему;
- до чого вона може призвести.

Ми підтвердимо отримання, перевіримо проблему, підготуємо виправлення через pull request і лише після цього розповімо подробиці.

Виправлення безпеки потрапляють у гілку `main`.

### Відомі обмеження

- Немає блокування акаунта після кількох невдалих спроб входу. Спроби видно лише в журналі.
- Застосунок підключається до Supabase одним користувачем бази з повними правами; окремої ролі з мінімальними правами немає.
- Панель адміністратора захищає лише вікно входу: `AdminDashboardService` роль не перевіряє.
- Старий пароль бази лишився в історії git. Переписувати історію не потрібно: пароль змінено, тому старий нікому не шкодить.

### Що робити, якщо секрет потрапив у репозиторій

1. Одразу змінити пароль у Supabase (Project Settings → Database → Reset database password).
2. Передати новий рядок підключення команді особисто й оновити user-secrets у всіх.
3. Закрити сповіщення Secret scanning як *Revoked*.
